🚪 index.js (Entry Point)

Loads environment variables, initializes Express, attaches global middleware (CORS, JSON body parser), and mounts routes.

🚦 routes/ (The Waiter)

Maps incoming HTTP methods and URL paths (e.g. POST /transactions) directly to controller functions.

🧠 controllers/ (The Chef)

Contains all business logic: runs input validation guards, computes math, and talks to MongoDB.

🔌 config/db.js (The Connection)

Establishes and shares a single persistent connection pool to MongoDB Atlas across the server.

🛡️ 3. Input Validation & Guard Clauses

In professional backend engineering, we use the Guard Clause Pattern (checking for bad input first and rejecting early) to keep our database clean.

Validation Decision Tree
flowchart TD
    Start["Incoming Request Body"] --> CheckType{"Is type 'income' OR 'expense'?"}
    
    CheckType -- No --> ErrType["🛑 Return 400: Invalid Type"]
    CheckType -- Yes --> CheckAmount{"Is amount a valid number > 0?"}
    
    CheckAmount -- No --> ErrAmount["🛑 Return 400: Invalid Amount"]
    CheckAmount -- Yes --> CheckCategory{"Is category non-empty string?"}
    
    CheckCategory -- No --> ErrCategory["🛑 Return 400: Category Required"]
    CheckCategory -- Yes --> CleanData["✨ Normalize: Number(amount), trim() strings, set default date"]
    
    CleanData --> SaveDB[("🍃 Save to MongoDB")]
    SaveDB --> Success["✅ Return 201 Created"]
💡 Why did we use && instead of ||?

if (!type || (type !== 'income' && type !== 'expense'))

If we used ||, the expression would always evaluate to true for every string in the universe, because a word can never be both 'income' AND 'expense' at the same time. Using && correctly checks that the input is neither one.

🍃 4. MongoDB Model & ObjectId Mechanics

In MongoDB, data is stored in JSON-like documents inside collections:

Transaction Document Schema
classDiagram
    class TransactionDocument {
        +ObjectId _id : "65f1a2b3c4d5e6f7a8b9c0d1"
        +String type : "income" | "expense"
        +Number amount : 1250.00
        +String category : "Salary" | "Food" | "Rent"
        +String date : "2026-09-01"
        +String description : "Monthly paycheck"
        +Date createdAt : 2026-09-01T14:30:00.000Z
    }
🔑 Why new ObjectId(id) is Required

MongoDB's _id is stored as a 12-byte binary BSON type, not a plain JavaScript string. If you query MongoDB with { _id: "65f..." } as a string, MongoDB will never find the match. We must convert it using new ObjectId(id) and always check ObjectId.isValid(id) first to avoid runtime crashes.
